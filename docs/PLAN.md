# 稳健理财产品推荐平台 — 可行性方案与计划

> 目标：聚合 **平安、招商、建设、网商、微众** 的理财产品 / 存款信息，按「**利率高优先 + 稳健优先**」做推荐排序；自动化脚本定时拉取数据，部署到服务器，通过网站访问。

> ✅ 已确认决策（2026-06）：
> - 数据源：以「中国理财网 + 银行官网公开页」为主，有更优来源可补充。
> - 技术栈：**前端 Vue 3 + Vite + Element Plus**；**后端 TypeScript + Node（Express）**；数据库 **SQLite**；**不使用 Docker**（直接起 Node 服务）。
> - 银行范围：**平安 / 招商 / 建设 / 网商 / 微众** 五家。
> - 部署：云服务器（Ubuntu），Node 进程 + 静态前端，PM2/systemd 守护 + cron 定时抓取。

---

## 1. 项目目标与核心诉求

| 优先级 | 诉求 | 在系统里的落地方式 |
| --- | --- | --- |
| 1 | 利率（收益）高 | 用「业绩比较基准 / 存款利率 / 7日年化」等字段做主排序键 |
| 2 | 稳健、不用天天操心 | 只收录低风险产品（理财 R1/R2、存款），并标注本金保障 / 风险等级 |
| 3 | 可部署、自动更新 | 定时脚本拉数据入库，前端只读展示，运维零干预 |

非目标（一期不做）：
- 不做交易 / 不接银行下单（只做信息聚合与推荐，不碰资金）。
- 不做「保本承诺」「投资建议」（合规红线，详见第 10 节）。

## 2. 需求拆解

### 2.1 功能需求
- 多银行产品列表：产品名称、所属银行、类型（活期理财 / 定期理财 / 定期存款 / 大额存单）、收益率、风险等级、起购金额、期限、起息日、数据来源、更新时间。
- 筛选与排序：按银行、按类型、按风险等级、按期限筛选；按收益率 / 风险排序。
- 「推荐」榜单：综合「收益高 + 风险低」的打分排序（见第 7 节）。
- 数据新鲜度：每条数据标注「最后更新时间」「来源链接」，过期数据降权或隐藏。

### 2.2 非功能需求
- 自动化：定时（如每日）跑爬虫脚本更新数据。
- 可部署：一条命令在云服务器上拉起（Docker Compose）。
- 可观测：抓取成功率、失败告警、日志留痕。
- 合规：尊重各站点 robots / 服务条款，控制抓取频率，明确「信息仅供参考」。

## 3. 数据来源分析（本项目最大难点，务必先验证）

银行**没有公开的官方开放 API**，数据获取主要靠「公开页面抓取」或「权威登记平台」。按可行性 / 合规性从高到低：

### 3.1 首选：官方 / 权威公开数据源（合规、稳定，推荐做 MVP）
| 数据源 | 覆盖内容 | 说明 |
| --- | --- | --- |
| **中国理财网 chinawealth.com.cn**（银行业理财登记托管中心） | 全市场银行理财产品：风险等级、业绩比较基准、净值、期限、管理人 | 官方权威，字段规范，是理财数据的**最佳来源**。可按管理人筛选「平安理财 / 招银理财 / 建信理财」 |
| 各银行**官网存款利率公示页** | 人民币存款基准 / 挂牌利率、整存整取等 | 存款利率法定需公示，相对稳定、好抓 |
| 各银行**官网 / 理财子公司官网产品页** | 在售理财产品、大额存单信息 | 字段不统一，需逐行适配 |

### 3.2 备选：第三方聚合站（数据丰富但合规/反爬风险高）
- 东方财富 / 天天基金、融360 等：覆盖广但有版权与反爬限制，仅作补充，不作为主源。

### 3.3 不采用：银行 APP 内部接口
- 需登录、有风控、属未授权访问，**法律风险高，明确排除**。

> ⚠️ 关键结论：**MVP 阶段以「中国理财网（理财）+ 三家银行官网存款利率页（存款）」为主数据源**。在写代码前，第 8 节「阶段 0」必须先人工验证这些页面的可抓取性（结构、是否动态渲染、是否需验证码），再决定 requests 还是 Playwright。

## 4. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 爬虫 | **TypeScript（Node）** + `axios` + `cheerio`；动态页可选 `Playwright` | 与后端同语言，统一维护 |
| 调度 | 服务器 `cron` 调 `npm run crawl` | 每日定时拉数据，简单可靠 |
| 数据库 | **SQLite**（`better-sqlite3`） | 轻量、零运维、单文件好备份 |
| 后端 API | **TypeScript + Express** | Node 生态成熟、起服务简单 |
| 前端 | **Vue 3 + Vite + Element Plus** | 表格筛选场景成熟 |
| 部署 | **裸 Node 进程**（PM2 / systemd 守护）+ 可选 Nginx 反代 | 不用 Docker，直接起 node 服务 |
| 服务器 | 1 台云轻量服务器（2C2G 起步即可） | 数据量小、读多写少 |

> 工程结构（npm workspaces 单仓多包）：`server/`（TS 后端 + 爬虫）、`web/`（Vue 前端）、`docs/`。生产环境后端可直接托管 `web` 构建产物（`web/dist`），单进程即可对外提供网站 + API。

## 5. 数据模型设计（草案）

```
Product (理财/存款产品)
├─ id                主键
├─ bank             银行：平安 / 招商 / 建设
├─ category         类型：活期理财 / 定期理财 / 定期存款 / 大额存单
├─ name             产品名称
├─ code             产品/登记编码（理财登记编码，去重用）
├─ risk_level       风险等级：R1/R2/...（存款记为「存款保险保障」）
├─ yield_type       收益口径：业绩比较基准 / 7日年化 / 存款利率
├─ yield_min        收益率下限(%)
├─ yield_max        收益率上限(%)
├─ term_days        期限（天，活期记 0）
├─ min_amount       起购/起存金额
├─ start_date       起息日 / 募集期
├─ principal_secured 是否本金保障（存款 True）
├─ source_name      来源（中国理财网 / xx银行官网）
├─ source_url       来源链接
├─ updated_at       数据更新时间
└─ raw_json         原始抓取数据（排错用）
```

去重键：`(bank, code)` 优先，无 code 时用 `(bank, name, term_days)`。

## 7. 推荐 / 排序算法（利率优先，稳健兜底）

一期用**可解释的规则打分**（不用黑盒模型，便于信任）：

```
score = 收益分(归一化收益率, 权重 0.6)
      + 稳健分(风险等级越低越高, 权重 0.3)
      + 新鲜度分(数据越新越高, 权重 0.1)
```

- 收益分：把同「期限档」内的收益率做 min-max 归一化，避免长短期不可比。
- 稳健分：存款=1.0，R1=0.9，R2=0.7，R3 及以上一期不收录（满足「不用天天担心」）。
- 默认展示：先按 `risk_level` 过滤为「存款 + R1 + R2」，再按 `score` 倒序。
- 用户可切换为「纯收益排序」，但默认是「稳健优先的高收益」。

## 8. 开发计划（按里程碑，非时间）

> 每个阶段都有明确「完成标志」，逐阶段验证再推进。

### 阶段 0 · 数据源可行性验证（最关键，先做）
- 人工打开中国理财网 + 三家银行存款利率页，确认：是否动态渲染、是否需验证码、字段在哪。
- 用脚本各抓 1 页样本，跑通「请求→解析→打印」。
- **完成标志**：能稳定抓到至少 1 家银行的真实产品/利率样本数据。
- 若此阶段受阻（强反爬/验证码），及时调整数据源策略。

### 阶段 1 · 项目骨架与数据建模
- 初始化 Python 工程（`pyproject.toml` / `requirements.txt`）、FastAPI、数据库、数据模型。
- **完成标志**：本地起服务，能对空库返回接口数据；DB 表建好。

### 阶段 2 · 采集脚本（三行三类）
- 实现「中国理财网理财」「银行存款利率」采集器，统一清洗 → 去重 → 入库。
- 加日志、失败重试、抓取频率限制。
- **完成标志**：跑一次脚本，三家银行数据真实入库。

### 阶段 3 · 后端 API + 推荐排序
- 列表 / 筛选 / 排序 / 推荐榜单接口，接入第 7 节打分。
- **完成标志**：接口能按「稳健优先高收益」返回正确排序。

### 阶段 4 · 前端页面
- 产品列表页（筛选 + 排序）、推荐榜单页、产品详情（含来源链接、更新时间、风险提示）。
- **完成标志**：浏览器可查、可筛、可排序。

### 阶段 5 · 部署与定时
- Docker 化、Nginx 反代、cron/APScheduler 每日更新、日志与告警。
- **完成标志**：云服务器公网访问，次日数据自动更新。

### 阶段 6 · 打磨
- 数据质量校验、异常告警、移动端适配、风险免责声明。

## 9. 部署方案
- `docker-compose` 编排：`web`（FastAPI）+ `db`（PG，或 SQLite 走卷）+ `nginx`。
- 定时任务：宿主机 `cron` 调 `docker compose exec web python -m crawler.run`，或应用内 APScheduler。
- 备份：每日 dump 数据库；日志按天滚动。
- 资源：2C2G 云服务器足够（数据量小、读多写少）。

---

## 10. 风险与合规（务必重视）
- **合规抓取**：遵守各站点服务条款与 robots，控制频率（如带延时、限并发），不抓登录态/非公开接口。
- **数据时效与免责**：页面显著标注「数据来自公开渠道，仅供参考，以银行官方为准」「过往业绩不代表未来收益」「理财非存款、不保本」。
- **不做投资建议 / 不承诺收益**：定位为「信息聚合与排序工具」，规避「荐股荐财」类合规风险。
- **存款保险**：存款类标注「受《存款保险条例》保障，50 万以内本息全额偿付」以体现「稳健」。
- **反爬应对**：优先官方权威源；必要时 Playwright 渲染；失败有重试与告警，绝不硬刚验证码。

## 11. MVP 最小范围（建议第一版只做这些）
1. 数据源：中国理财网（平安理财/招银理财/建信理财）+ 三家银行官网存款利率。
2. 只收录：定期存款 / 大额存单 + R1/R2 理财。
3. 一个采集脚本 + SQLite + FastAPI + 一个列表页（带「稳健优先高收益」排序 + 风险提示）。
4. Docker 一键部署 + 每日定时更新。

> 先用 MVP 验证「数据能不能稳定拿到、排序合不合理」，再扩展银行与品类。

## 12. 落地说明（已确认，进入实现）
- 已按第 0 段「已确认决策」搭建：`server`（TS/Express/better-sqlite3）+ `web`（Vue3/Vite/Element Plus）。
- 爬虫采用「适配器接口 + best-effort 真实抓取 + 种子示例数据」并行：
  - 适配器接口统一产出 `RawProduct`，便于逐家银行补齐真实解析。
  - **种子数据**为基于公开渠道整理的代表性示例，界面明确标注「示例/参考」，保证平台先端到端可用。
  - 真实抓取需结合各站点结构（部分动态渲染/反爬）逐步完善，失败有重试与降级。
- 运行方式见根目录 `README` 与 `AGENTS.md`：`npm install` → `npm run crawl`（入库）→ `npm run dev`（前后端开发）。
